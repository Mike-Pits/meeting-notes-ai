# Итоги встреч

Локальное учебное приложение: текст и документы, аудиозаписи, расшифровка на GPU, структурированные итоги, поручения и экспорт. Интерфейс и результаты на русском. Рабочие материалы хранятся в `data/` на этом компьютере.

## Запуск на текущем компьютере

В папке `Lesson_02` выполните:

```bash
bash scripts/run.sh
```

Откройте [приложение](http://127.0.0.1:8765). Терминал оставьте работающим. Закрытие вкладки не останавливает принятые задания; Ctrl+C в терминале останавливает приложение. После повторного запуска прерванное задание можно повторить кнопкой. Не запускайте несколько экземпляров приложения в одной папке данных.

Зависимости и обе модели уже установлены в этой рабочей папке. Системный драйвер NVIDIA не изменялся. При запуске из ограниченной среды без `/dev/nvidia*` GPU недоступен: запускайте из обычного терминала пользователя.

## Установка в новую копию

Нужны Ubuntu, Python 3.12 с venv, FFmpeg/ffprobe, curl, tar с zstd и рабочий драйвер NVIDIA. Проверенный GPU — RTX 4070 Laptop 8 ГиБ; оперативная память около 30 ГиБ. Потребуется свободное место для окружения, моделей и записей, ориентир — не менее 15 ГБ плюс данные.

```bash
bash scripts/setup.sh
bash scripts/download-models.sh
bash scripts/run.sh
```

Интернет нужен только для установки. Зависимости фиксируются в `requirements.lock.txt`. Конкретный проверенный идентификатор Qwen указан в `TEST_REPORT.md`; скачивание по тегу может со временем дать другую сборку, после замены модели повторите эталонные проверки. Модели хранятся в `.models/`, бинарный Ollama — в `.runtime/`, Python — в `.venv/`. Для альтернативного пути данных задайте `MEETINGS_DATA`; по умолчанию используется `data/` рядом с приложением.

## Работа со встречей

1. Создайте встречу, введите название и дату.
2. Вставьте текст или загрузите TXT в UTF-8, DOCX, PDF с текстовым слоем. Импорт документа заменяет текст с подтверждением. Предел — 200 000 символов, файл до 50 МБ.
3. Для аудио загрузите MP3/WAV/M4A до 500 МБ и 60 минут, нажмите «Расшифровать». Проверьте имена, числа и сроки в полученном тексте. Затем отдельно нажмите «Проанализировать текст».
4. Проверьте новый результат и цитаты. Ответьте на уточнения по поручениям или явно отметьте «Не указано». Можно исправлять, добавлять и убирать решения и поручения. Цитата должна присутствовать в исходной редакции текста.
5. Подтвердите результат. Статусы поручений меняются вручную; сохраните правки перед экспортом.
6. Для повторного анализа исправьте текст и запустите обработку. Новый результат не заменяет сохранённый до подтверждения. Замена стирает прежние правки и возвращает статусы к «Не начато».

Исходники и подтверждённые результаты сохраняются между запусками. Удаление встречи удаляет их из приложения; уже скачанные Markdown/DOCX-копии остаются в папке загрузок пользователя. Резервные копии и шифрование папки данных средствами приложения не реализованы.

## Запись из браузера

«Записать встречу» запрашивает источник звука встречи и микрофон. Если Chrome/Chromium на Ubuntu не предоставляет аудиодорожку настольного приложения, приложение сообщает об этом и предлагает готовый файл. Наличие дорожки ещё не доказывает, что выбран правильный источник: перед сохранением прослушайте обе стороны.

Доступны пауза, продолжение, остановка, прослушивание и удаление несохранённой записи. Закрытие вкладки прекращает живую запись. Обработка уже загруженного аудио от вкладки не зависит. Разрешения микрофона и выбор источника выполняет пользователь. Пользователь подтвердил запись звука YouTube и собственной речи с микрофона при последовательном звучании источников, расшифровку и анализ; пункт записи закрыт в протоколе тестирования. Реальный созвон и одновременное наложение источников отдельно не проверялись.

## Проверки

```bash
.venv/bin/python -m pytest -q
PYTHONPATH="$PWD" .venv/bin/python scripts/benchmark.py
.venv/bin/python scripts/verify_benchmark.py
```

Для benchmark нужен запущенный Ollama на порту 11435; не запускайте benchmark одновременно с заданиями приложения. Скрипт использует четыре синтетических материала из `fixtures/`, результаты пишет в `data/ai-benchmark.json`. Тесты приложения используют временную БД и не меняют пользовательские встречи. В ограниченной агентской среде TestClient может зависать; в обычном терминале проверки проходят.

`SRS.md` — требования, `PLAN.md` — этапы, `TEST_REPORT.md` — что действительно проверено и что ещё не подтверждено. Синтетическая речь не подтверждает качество на реальных созвонах. Автоматическая проверка цитат не заменяет смысловую проверку человеком.

Офлайн-проверка в отдельном сетевом пространстве (Linux, не меняет сеть хоста; нужны подготовленные синтетические файлы из `data/`): `unshare --user --map-root-user --net scripts/offline-check.sh`. Она поднимает отдельные процессы и временную БД, проверяет недоступность внешней сети, выполняет расшифровку, анализ, сохранение и экспорт.
