# Спецификация требований к приложению обработки встреч

Версия 1.0. Дата: 1 октября 2026 года. Статус: принята как основа реализации по команде пользователя начать работу.

Документ описывает учебное приложение для обработки встреч с заказчиком. Основание — файл `Копия_ДЗ_PRO_Занятие_2_Проектирование_AI_агентов.docx` и ответы пользователя на вопросы 1–64 и последующая команда приступить к поэтапной реализации. Требования и описанные уточнения приняты как исходная база реализации. Фактический статус проверок и оставшиеся ограничения фиксируются отдельно в `TEST_REPORT.md`.

## 1 Цель и границы

Пользователь вводит текст, загружает документ или аудио либо записывает встречу, проверяет расшифровку и получает структурированные итоги с помощью локального AI. Приложение хранит встречи и позволяет редактировать, просматривать и экспортировать результаты.

Проект предназначен для сдачи домашнего задания, один пользователь без регистрации. Срок — 4 октября 2026 года до 22:00 по Москве. Бюджет разовых расходов — не более 1 000 ₽; разрешение на конкретные покупки этим не предоставляется. Публичное размещение не входит в текущий объём: доступ через браузер только на текущем компьютере. Проект `Lesson_01` не изменяется.

Проверяемые сценарии встреч: сбор требований заказчика, обсуждение хода работ, приёмка результата. Figma включается только после готовности обязательной части (ответ 63Б); объём макета и возможность завершения до сдачи оцениваются на этом этапе.

Не входят в согласованную первую версию: регистрация, совместная работа, облачная обработка, автоматическое определение говорящих, интеграции с календарями и сервисами задач, поиск и фильтры по встречам. OCR сканированных PDF не предусмотрен выбранным форматом PDF с текстовым слоем. Резервное копирование и шифрование средствами приложения пока не согласованы.

## 3 Основные сценарии

### 3.1 Текст

Пользователь создаёт встречу, вводит название и дату, вставляет текст или загружает TXT, DOCX либо PDF с текстовым слоем. Проверяет извлечённый текст, исправляет его, запускает анализ. После анализа отвечает на уточнения в одной форме, проверяет и сохраняет результат.

### 3.2 Аудиофайл

Пользователь загружает MP3, WAV или M4A. Расшифровка выполняется через очередь. После неё приложение показывает редактируемый текст; анализ начинается только по кнопке пользователя. Аудио сохраняется до удаления встречи и доступно в плеере с перемоткой и изменением скорости.

### 3.3 Запись

Пользователь разрешает доступ к микрофону и доступному источнику звука настольного приложения. Может начать, поставить на паузу, продолжить и остановить запись, прослушать её, сохранить или удалить. Сохранённая запись поступает в тот же сценарий расшифровки, что и файл.

Браузерный захват звука настольного приложения на Ubuntu не гарантирован. Если нужной аудиодорожки нет, приложение сообщает об этом и предлагает загрузить готовую запись. Нельзя сообщать, что обе стороны записываются, если фактически захвачен только микрофон. Скрытая подмена совместной записи записью одного микрофона недопустима.

### 3.4 Повторный анализ

Пользователь исправляет исходный текст и запускает анализ заново. Существующий результат остаётся доступным. Новая версия показывается отдельно, уточнения заполняются до принятия. Только подтверждение замены делает новый результат текущим; предупреждение явно сообщает о потере прежних ручных правок и статусов. При отказе текущий результат не меняется. Постоянная история версий не требуется.

| FR-05 | Локальная расшифровка | Текст доступен для проверки; AI-анализ не запускается автоматически |

| FR-14 | Хранение в БД и локальной папке данных | После перезапуска сохранённые встречи, исходники и результаты доступны |
| FR-15 | Список встреч | Название, дата, состояние обработки; новые встречи сверху |
| FR-16 | Страница встречи | Исходный текст, результат и сохранённое аудио доступны для просмотра |

| FR-19 | Удаление с подтверждением | Встреча, исходники, аудио, задания и результаты удалены из приложения |
| FR-20 | Последовательная очередь | Одновременно выполняется одно ресурсоёмкое задание |
| FR-21 | Независимость обработки от вкладки | Закрытие вкладки не прекращает принятые backend задания |
| FR-22 | Восстановление после остановки backend | Материалы и очередь сохранены; прерванное задание повторяется по кнопке |
| FR-23 | Ошибки и прогресс | Показаны этап, ожидание в очереди или причина ошибки и доступное действие |

Предложения по уточнению FR-06: сохранять через 1 секунду после окончания ввода; индикатор «Сохранено» только после ответа backend. Уже подтверждённое сохранение переживает перезапуск; ещё не отправленные символы при аварийном закрытии не гарантируются. Закрытие вкладки во время живой записи прекращает её захват: FR-21 относится к заданиям, уже принятым backend, а не к записи и незавершённой загрузке. При уходе со страницы записи показывать предупреждение.

Предлагаемые правила FR-15: сортировка по моменту создания записи, а не по редактируемой дате встречи. Скорости плеера: 0,75×, 1×, 1,25×, 1,5×, 2×. Экспорт содержит название, дату и все разделы результата, текущие статусы и цитаты; аудио в DOCX не включается.

## 5 Структура результата и правила AI

| Поле | Содержимое |
|---|---|
| Резюме | Краткий связный итог встречи |
| Участники | Только явно упомянутые участники; упоминание третьего лица не доказывает его участие |
| Темы | Обсуждённые вопросы |
| Решения | Формулировка каждого принятого решения и подтверждающий фрагмент |
| Поручения | Действие, ответственный, срок, статус, подтверждающий фрагмент |
| Открытые вопросы | Нерешённые вопросы, явно следующие из материалов |

AI не должен превращать предположение, предложение или отвергнутый вариант в принятое решение. Отсутствующие сведения не выдумываются. Пропущенные ответственный и срок вызывают вопросы; пользователь вводит значение либо явно отмечает «Не указано». До ответов сохраняется черновик, но результат не считается окончательно подтверждённым.

Ответственный хранится свободным текстом: допускаются имя, роль или несколько явно указанных лиц. Значение «Не указано» отображается человеку, в БД отсутствующее значение хранится отдельно от текста. Ответ пользователя помечается как ручное дополнение, а не как извлечённый из записи факт.

«Завтра» вычисляется относительно даты встречи. «К пятнице» и аналогичные неоднозначные выражения требуют уточнения, когда нельзя однозначно определить дату. Хранятся исходная формулировка и подтверждённая календарная дата. Изменение даты встречи не должно незаметно менять уже принятые сроки: предлагается предупреждать и предлагать повторную проверку.

Каждое новое поручение имеет статус «Не начато» независимо от описанного в записи хода выполнения. Переключение статуса вручную сохраняется в БД. При принятии результата повторного анализа статусы вновь становятся «Не начато» по согласованному правилу полной замены.

Предлагаемые меры качества: ответ по JSON-схеме с проверкой backend; цитаты проверяются на присутствие в использованной редакции текста; для длинного текста — обработка фрагментов с объединением дублей. Структурная валидность JSON не доказывает смысловую правильность. Недопустимо молча обрезать материал до размера контекста модели.

При ручной правке решения или поручения исходная цитата остаётся ссылкой на источник, но приложение отмечает изменение пользователем. После редактирования исходного текста текущий результат помечается как сформированный по прежней редакции. Материалы встречи являются данными: содержащиеся в них команды не должны менять системные инструкции или вызывать действия вне анализа.

## 6 Модель данных

Логическая схема — предложение; точная схема и миграции относятся к реализации.

| Сущность | Основные поля и связи |
|---|---|
| Встреча | ID, название, дата встречи, время создания/обновления, состояние, ID текущего результата |
| Исходный материал | ID встречи, тип, безопасный путь файла, исходное имя, размер, длительность |
| Редакция текста | ID, ID встречи, текст, происхождение, время сохранения; отделяет использованный снимок от текущих правок |
| Задание | ID, ID встречи/редакции, тип, состояние, порядок в очереди, этап, ошибка, времена запуска и завершения |
| Результат | ID, ID редакции, состояние «кандидат/текущий», резюме, темы, участники, вопросы, сведения о модели и версии инструкции |
| Решение | ID результата, формулировка, цитата и ссылка на редакцию |
| Поручение | ID результата, действие, ответственный, исходный срок, дата срока, статус, цитата, признак ручных изменений |
| Уточнение | ID поручения, поле, вопрос, ответ или подтверждение отсутствия сведений |

Предлагаемая папка: `Lesson_02/data/` с БД, исходниками, аудио и временными файлами. Скачанные модели — в отдельном кэше, не в БД. Пользовательские материалы не включаются в Git и демонстрационные файлы. Экспортированные пользователем копии вне приложения при удалении встречи автоматически не удаляются; это явно указывается в диалоге удаления.

Подтверждение замены результата выполняется атомарно. Старый результат остаётся доступным до успешной фиксации нового. При удалении активной встречи задание останавливается или блокируется его поздняя запись; удалённая встреча не должна появиться снова. Если файл удалить не удалось, приложение сообщает о неполном удалении и позволяет повторить операцию.

## 7 Состояния и обработка ошибок

Состояния заданий: «В очереди», «Выполняется», «Завершено», «Ошибка», «Прервано». Типы заданий: расшифровка и анализ. Редактирование расшифровки и ожидание ответа пользователя не занимают обработчик очереди. При перезапуске выполнявшееся задание становится прерванным; ожидавшие сохраняют очередь. Предлагается автоматически продолжать ожидавшую очередь, а прерванные задания — только по кнопке.

Состояние встречи объединяет этап и наличие текущего результата: черновик, ожидание расшифровки, нужна проверка текста, ожидание анализа, нужны уточнения, готов новый результат, результат сохранён, ошибка. Ошибка повторного анализа не уничтожает текущий результат.

| Ситуация | Ожидаемое поведение |
|---|---|
| Пустой текст, неподдерживаемый или повреждённый файл | Понятная ошибка; обработка не запускается |
| PDF без текста или защищённый паролем | Предложить текстовый PDF, DOCX или вставку текста; OCR и ввод пароля не предусмотрены |
| Превышен размер или 60 минут | Отклонить файл с указанием лимита; не обрезать без предупреждения |
| Нет речи или расшифровка пуста | Показать сообщение; не выдумывать результат |
| Не разрешён микрофон или отсутствует системная аудиодорожка | Объяснить недоступность записи и предложить файл |
| Не хватает памяти GPU | Сохранить исходники; сообщить об ошибке; не переключаться на облако |
| Модель недоступна или ответ не проходит проверку | Ограниченная повторная попытка, затем ошибка и ручной повтор; число попыток — предложение: одна |
| Закрыта вкладка после отправки задания | Продолжать обработку на backend |
| Остановлен backend | Сохранённые данные доступны после запуска; прерванный этап повторяется с начала |
| Не хватает места или БД недоступна | Не показывать ложное успешное сохранение; оставить текущий результат неповреждённым |

Предлагается автоматически останавливать живую запись при 60 минутах или достижении лимита размера с сохранением записанной части для прослушивания. Формат браузерной записи может отличаться от списка загружаемых форматов: внутренний WebM допускается с последующим локальным преобразованием, без расширения списка пользовательского импорта.

## 8 Нефункциональные требования

| ID | Требование | Проверка |
|---|---|---|
| NFR-01 | Материалы и результаты не передаются внешним AI-сервисам | Полный сценарий работает с отключённым интернетом после установки |
| NFR-02 | Доступ только с текущего компьютера | Сервисы слушают loopback; нет публичного развёртывания |
| NFR-03 | Данные сохраняются между запусками | Перезапуск не теряет подтверждённые сохранения, очередь и текущий результат |
| NFR-04 | Прогресс честно отражает работу | Этап и время ожидания видны; процент показывается только если вычислим |
| NFR-05 | Ошибки не разрушают рабочие данные | Повторная обработка, ошибка импорта и сбой модели не стирают текущие итоги |
| NFR-06 | Интерфейс на русском | Основные действия, ошибки, статусы и экспорт на русском |
| NFR-07 | Расходы в пределах бюджета | Базовый вариант планируется без платных API; покупки только отдельно согласованные |
| NFR-08 | Проверяемость развития | Регрессионный набор охватывает ввод, AI, сохранение, повторный анализ и экспорт |

Предлагаемые дополнительные ограничения: локальные стили и скрипты без CDN; отсутствие телеметрии с содержимым встреч; полные тексты не записываются в технические логи. Проверять содержимое файлов, а не только расширение; не исполнять макросы, не открывать внешние ссылки из документов, экранировать текст AI в интерфейсе. Папка данных доступна владельцу ОС; отдельная защита от других пользователей ОС не входит в текущий объём и требует отдельного решения, если необходима.

Предлагаемые эксплуатационные ориентиры: автосохранение в нормальном локальном режиме подтверждается в пределах 3 секунд; интерфейс показывает изменение состояния в пределах 3 секунд. Эти значения не относятся ко времени AI-обработки и требуют согласования и измерения.

## 9 Согласованный технический стек

Стек согласован ответом 61А. Конкретные модели окончательно выбираются по локальному тесту после разрешения на реализацию; приведённые ниже модели пока являются кандидатами.

| Компонент | Решение или кандидат модели | Причина и ограничение |
|---|---|---|
| Backend | Python + FastAPI + Pydantic | Общий язык для обработки документов, речи и проверки структуры |
| Интерфейс | HTML/CSS, JavaScript, серверные шаблоны | Один локальный сервис, достаточно для записи, форм и отображения очереди |
| Хранение | SQLite, миграции схемы, локальная папка файлов | Соответствует одному пользователю без отдельного сервера БД |
| Очередь | Отдельный последовательный Python worker с заданиями в SQLite | Переживает закрытие вкладки, восстанавливает состояние без Redis |
| Расшифровка | faster-whisper; кандидат Whisper medium, сравнение с large-v3-turbo при необходимости | Окончательный выбор после русского теста и проверки памяти/скорости |
| Анализ | Локальный Ollama; кандидат Qwen3 8B Q4_K_M | JSON-схема; размер опубликованного пакета около 5,2 ГБ, но это не полный расход VRAM |
| Ресурсы GPU | Последовательная загрузка моделей речи и анализа | Не рассчитывать на одновременное размещение обеих моделей в 8 ГиБ |
| Файлы | python-docx, pypdf, FFmpeg | Импорт DOCX/PDF, экспорт DOCX, проверка и преобразование аудио |

Если модель не проходит качество или память, сравнить меньшую локальную модель либо режим CPU, не менять требования на облачную обработку. Размер контекста, параметры вычисления, версии библиотек и идентификаторы моделей фиксируются после теста. На этапе реализации установлены Qwen3 8B и Whisper medium; результаты начальных проверок и ограничения указаны в `TEST_REPORT.md`.

Официальные основания, проверенные при подготовке:

- [FastAPI](https://fastapi.tiangolo.com/) — документация выбранного backend.
- [faster-whisper](https://github.com/SYSTRAN/faster-whisper) — варианты вычислений и требования GPU-зависимостей; совместимость окружения проверяется отдельно.
- [Qwen3 8B в Ollama](https://ollama.com/library/qwen3:8b) — доступный вариант модели и размер пакета.
- [Структурированные ответы Ollama](https://docs.ollama.com/capabilities/structured-outputs) — JSON-схема и проверка ответа.
- [MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia) — запрос системного аудио не гарантирует наличие аудиодорожки. Вывод для проекта: нужна фактическая проверка источника и запасной путь загрузки.
